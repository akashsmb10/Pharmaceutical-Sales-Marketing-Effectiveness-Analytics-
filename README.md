# Pharmaceutical Sales & Marketing Effectiveness Analytics

> **Synthetic/simulated portfolio project.** This repository contains no real patient, physician, client, pharmaceutical-company, prescription, or campaign data. All records, names, revenue values, targets, and results are generated locally for learning and demonstration only.

## Business question

How can a fictional pharmaceutical commercial team describe prescription activity, revenue, territory performance, physician activity segments, and observed campaign responses in a reproducible analytics workflow?

This project supports descriptive investigation. It does **not** estimate campaign uplift, return on investment, causal impact, clinical outcomes, or real-world market performance.

## Data provenance and permitted use

The five CSV files in `data/` are generated by `run.py` using NumPy's deterministic random-number generator with seed `360`. No external dataset is downloaded or used. Therefore, no third-party dataset licence applies. The data may be regenerated locally by running the project; do not represent it as public or proprietary pharmaceutical data.

The generator deliberately creates physician-month facts, non-random campaign contact selection, seasonality, zero prescription months, varying illustrative prices, campaign costs, and response outcomes. Its rules are assumptions embedded in code, not observed commercial behavior. SHA-256 hashes and package versions are written to `outputs/validation.json` after each successful run.

## Data model

```text
territory (1) ──< physician (1) ──< prescription_month
                         │
                         └────────< outreach >──────── (1) campaign
```

`prescription_month` has one row per physician and month, including zero-prescription months. `outreach` has at most one recorded contact per physician and month. See [the data dictionary](docs/data_dictionary.md) for every field, key, grain, and limitation.

## Included analysis

- Integrity validation for duplicates, required values, valid ranges, foreign keys, and complete 12-month physician coverage.
- SQLite views for monthly performance and growth, territory performance, activity-based physician segments, campaign response summaries, and campaign response by segment.
- A Plotly HTML exploratory dashboard at `outputs/dashboard.html` after a run.
- Reconciliation checks between source facts and SQL-view aggregates.

The executed Python path uses SQLite. A MySQL 8 schema, CSV-load workflow, audit queries, and analytical views are supplied in `sql/`; see [the MySQL runbook](docs/mysql_runbook.md). MySQL execution has not yet been verified in this workspace. A Power BI report is not yet included.

## Reproduce on Windows

```powershell
cd pharmaceutical-sales-marketing-analytics
.\.venv-p1\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run.py
python -m pytest -q
```

Expected verification: `validation.json` reports `data_type` as `synthetic`, `sql_reconciliation` as `PASS`, and the test suite reports five passing tests.

## Outputs and interpretation

Generated outputs include CSV extracts, `analytics.sqlite`, `dashboard.html`, `findings.md`, and `validation.json`. They are reproducible generated artifacts and are not committed as a source-of-truth dataset.

Treat campaign response comparisons as descriptive only: physicians are selected for contact non-randomly in the simulation, so contacted and non-contacted populations are not comparable for causal inference. Before a real resource-allocation decision, stakeholders would need agreed commercial definitions, data-quality review, and a pre-specified experimental or quasi-experimental design.

## Current limitations

- Entirely synthetic and illustrative; not valid for real market, client, or clinical decisions.
- The MySQL scripts are provided but unverified against a local MySQL server in this workspace.
- Physician segments are retrospective activity groupings, not prescribing recommendations.
- No Power BI `.pbix`, dashboard screenshots, or Power BI build guide is included yet.
- No product table or product-level sales fact exists in the current generator.
- Territory labels are synthetic placeholders, not geographic territories.
